# Multi-season league economy and autonomous front offices

The franchise universe now carries one cap-and-decision context into every new
season. The 2026–27 NBA system levels remain the official base year. Later cap
years are explicitly labeled planning projections and compound the existing
eight-percent assumption across the salary cap, minimum team salary, tax line,
both aprons and every mid-level exception.

## One active economic context

The current season's rules feed the cap sheet, transaction checker, free-agent
offers, maximum salaries, trade matching, apron restrictions, ownership payroll
ceilings and general-manager reviews. This prevents a future payroll from being
judged against frozen 2026–27 thresholds. The Trade Center also advances its
planning deadline with the league year.

Every rollover already forces a league-wide organizational review. All 30 front
offices reassess present strength, record, recent form, roster age, health,
payroll, needs and draft capital. Their persistent direction—contend, compete,
retool or rebuild—conditions protected cores, trade blocks, budget ceilings,
risk tolerance and transaction acceptance. Weekly CPU-to-CPU trade windows run
through the same CBA and value gates exposed to the user.

## Optional local strategic identities

The next layer inside this priority is a local-only micro-model runtime serving
one persistent coach and general-manager identity for each team. It is a
strategy and personality layer, not an authority. Deterministic engines continue
to own ratings, player value, legality, health, simulation results and hard
acceptance thresholds. Local identities may rank validator-approved choices,
form plans, negotiate and explain decisions; a deterministic fallback remains
available for every decision window.

## Accuracy contract

- Official and projected economic data are never presented as equivalent.
- All thresholds for a season advance together from one immutable rules object.
- Long simulations never switch to a lower-fidelity game or transaction model.
- User and CPU teams share the same legality, valuation and roster constraints.
- Save replay remains deterministic when the optional local identity layer is
  disabled.
